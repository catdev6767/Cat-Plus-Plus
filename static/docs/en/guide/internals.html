Internals — How Cat++ Works

Deep understanding of interpreter: from source code to output.

1. Pipeline

Source code (.cat)
        │        ▼


┌───────────────────┐
│  Lexer            │  Read → Token Characters
│  (tokenize)       │
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│  Parser           │  Token → AST
│  (recursive       │
│   descent)        │
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│  Interpreter      │  Browse AST
│  (tree-walking)   │  → execution
└────────┬──────────┘
         │
         ▼
      Output

2. Lexer

Read fromng characters, generate tokens. Processing:

  • Number: 42, 3.14, 0xFF, 0b1010
  • String: "hello" with escape \n \t \"
  • Identifiers: foo, bar_baz
  • From course:meow, paw, purr
  • Operator:+ - * / % == != & | << >>
  • Layout: INDENT, DEDENT, NEWLINE

Examples

paw x = 42

Tokenize to:

PAW("paw")  IDENT("x")  ASSIGN("=")  NUMBER(42)  NEWLINE

3. Parser

Get tokens, create AST (Abstract Syntax Tree). Userecursive descent— each function parse a type of structure.

Precedence chain (from low to high)

expr
 ├── or_          (or, either)
 ├── and_         (and, with)
 ├── not_         (not, never)
 ├── in_          (in)
 ├── bit_or       (|)
 ├── bit_xor      (^)
 ├── bit_and      (&)
 ├── shift        (<<, >>)
 ├── cmp          (==, !=, <, >, <=, >=)
 ├── add          (+, -)
 ├── mul          (*, /, %)
 ├── unary        (-, ~)
 └── postfix      (call, index, dot)

Examples AST

paw x = 1 + 2 * 3

Parse to:

('let', 'x',
  ('+', ('num', 1),
        ('*', ('num', 2), ('num', 3))))

(expression) or*has a higher precedence+, should 2*3is the previous group.

4. Interpreter

Browse AST. Each node has a functioneval_()(expression) orexec_()Statement

Environment (scope)

class ENV:
    vars: dict          # variable in this scope
    parent: ENV         # scope parent

When searching for the variable `x`:
1. If x in vars → returns
2. If not → found in parent (recursive)
3. If there is no → fault

Examples scope

paw x = 10          # global

purr f()
    paw y = 20      # local
    meow x          # read is x (global)
    meow y          # read is y (local)

f()                 # OK
meow y              # ERROR — y only exists in f

6. Exceptions

Use Python exception to control flow:

  • ReturnEx— exit function return value
  • StopEx— exit loop (sit)
  • SkipEx— skip iteration (leap)
  • CatError— runtime error (divided by 0, undeclared variable)
# When `give x` is encountered:
raise ReturnEx(value)

# In function:
try:
    for stmt in body: exec_(stmt)
except ReturnEx as e:
    return e.v.

7. Module system

3 file:

  • core/registry.py— API registration between modules
  • core/bus.py — event bus
  • core/loader.py — auto-load modules

Interpreter register with registry:

class InterpreterModule(BaseModule):
    def setup(self):
        self.registry.set('interpreter', self)

    def run(self, code):
        return run_catpp(code)

Other modules called through the registry:

interp = self.registry.get('interpreter')
result = interp.run("meow \"hi\"")

8. Web IDE

Frontend sends the code to the server via POST/api/run:

POST /api/run
Content-Type: application/json

{"code": "meow \"hello\""}

Server calls interpreter:

output = run_catpp(code, timeout=5.0)
return {"ok": True, "output": output}

9. Transpiler Cat++ → C

Other with interpreter. Not implement AST butsinh C code.

# Cat++ AST

# C code sinh ra

Use 2-pass:

  1. Pass 1: scan struct, infer return types
  2. Pass 2: generate C code

10. Performance limitations

Interpreter tree-walking slower C approx.100xReason:

  • Each AST (function call overhead) browsing expression
  • Dynamic type (check type runtime)
  • Python VM (slower native)
  • None JIT

Want faster:

  • Compile to bytecode (nhanh 5-10x)
  • Transpile C (almost as fast as C)
  • JIT with LLVM (C fast)
